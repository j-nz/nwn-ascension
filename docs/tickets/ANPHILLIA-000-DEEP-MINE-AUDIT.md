# ANPHILLIA-000 — Deep-mine integration audit and donor guardrails

**Status:** OPEN  
**Type:** Programme / governance  
**Donor:** https://github.com/mtijanic/anphillia

## Objective
Turn the Anphillia source mine into a governed Ascension implementation programme and prevent obsolete donor architecture being imported wholesale.

## Already absorbed or superseded
Do **not** re-import these wholesale: eE encounter framework; PAT PvE AutoTune stat architecture; persistent personal chests; database dialogue framework; generated loot/equipment framework; NPC randomisation; terrain trigger framework; True Seeing replacement; legacy EAS arrays; party-join teleport; global stealth-entry cooldown.

Ascension's current encounter signal graph, mob-balancing pipeline, Campaign DB storage, conversation architecture, low-magic loot, investigation/stealth systems and NWN:EE-era data structures remain authoritative.

## Programme rules
1. Every child ticket must compare the current Ascension implementation before coding.
2. Record exact donor files actually used.
3. Adapt concepts to current naming/persistence/chat/door/encounter/balancing standards; never transplant donor architecture blindly.
4. Preserve stock-asset compatibility.
5. Update !commands for new player-facing commands.
6. Compile and regression-test each implemented subsystem.
